## The core problem

<Summary>
Client and server are written in different languages and can't understand each other's in-memory data. They need a common format both agree on.
</Summary>

JavaScript is dynamic and loosely typed. Rust is compiled with strict types. Neither can read the other's memory, so both write and read a shared text format instead.

## What is serialization?

<Summary>
**Serialization:** native data → common format (JSON) before sending. **Deserialization:** common format → native data after receiving.
</Summary>

Serialization makes communication **language-agnostic**: any machine can talk to any other, as long as both agree on the format.

## Text vs binary formats

<Summary>
Text formats (JSON, XML, YAML) are human-readable and a bit bigger. Binary formats (Protobuf, Avro) are raw bytes: smaller and faster, but you need a tool to read them.
</Summary>

| Category | Examples | When used |
| --- | --- | --- |
| Text | JSON, XML, YAML | REST APIs, config files, logs |
| Binary | Protobuf, Avro | High-performance service-to-service |

The same user, `{ name: "Ali", age: 25 }`, in both:

```json
{"name":"Ali","age":25}
```

```bash
# Protobuf (schema: name = field 1, age = field 2): 7 bytes instead of 23
0a 03 41 6c 69 10 19
```

JSON is the default for REST APIs. You'll rarely use XML or binary formats unless a system requires it.

## JSON rules

<Summary>
Keys in double quotes. Values: string, number, boolean, null, array or object. No comments, no trailing commas.
</Summary>

JSON (JavaScript Object Notation) isn't limited to JavaScript; every language reads and writes it. It's used in REST requests and responses, log files, and config files like `package.json` and `tsconfig.json`.

- A JSON document can be **any** JSON value: an object `{…}`, an array `[…]`, a string, a number, `true`/`false`, or `null`. It doesn't have to start with `{`.
- All keys must be strings in **double quotes**: `"name"`, not `name` or `'name'`.
- Values can only be: string, number, boolean, `null`, array, or another object.
- No comments.
- No trailing commas.

## The backend engineer's mental model

<Summary>
Data crosses many network layers, but by the time it reaches your server the network has reassembled exactly the JSON string the client sent. You work at the **application layer**.
</Summary>

## Code: serialize and deserialize in Node

<Summary>
`JSON.stringify()` serializes and `JSON.parse()` deserializes. In Express, `express.json()` and `res.json()` do both for you.
</Summary>

```js
const user = { name: 'Ali', age: 25 }

const jsonString = JSON.stringify(user) // SERIALIZE → '{"name":"Ali","age":25}'  (string)
const jsObject = JSON.parse(jsonString) // DESERIALIZE → { name: 'Ali', age: 25 }  (object)
```

**What Express does automatically:**

```js
app.use(express.json()) // deserializes every JSON request body (without it, req.body is undefined)

app.post('/users', (req, res) => {
  const user = req.body // already a JS object
  res.status(201).json({ created: user }) // serializes + sets Content-Type: application/json
})
```

**Without Express**, this is the work `express.json()` and `res.json()` hide:

```js
const http = require('http')

http.createServer((req, res) => {
  if (req.method === 'POST' && req.url === '/users') {
    let body = ''
    req.on('data', (chunk) => (body += chunk)) // collect raw chunks from the stream
    req.on('end', () => {
      let user
      try {
        user = JSON.parse(body) // manually deserialize
      } catch {
        res.writeHead(400, { 'Content-Type': 'application/json' })
        return res.end(JSON.stringify({ error: 'invalid JSON' })) // bad JSON must not crash the server
      }
      res.writeHead(201, { 'Content-Type': 'application/json' })
      res.end(JSON.stringify({ created: user })) // manually serialize
    })
  }
}).listen(3000)
```

<Callout type="trap">
`JSON.parse` **throws** on invalid input. `express.json()` catches that and replies `400 Bad Request`, but when you parse by hand, wrap it in try/catch, or one bad request body crashes the process.
</Callout>

## Quick revision

| Term | One line |
| --- | --- |
| Serialization | Your data **into** JSON before sending |
| Deserialization | JSON back **into** your data after receiving |
| JSON | Text-based, human-readable, the standard for REST APIs |
| Binary formats | Protobuf, Avro: smaller and faster, not human-readable |
| `JSON.stringify()` | JS value → JSON string |
| `JSON.parse()` | JSON string → JS value (throws on invalid input) |
| `express.json()` | Auto-deserializes every JSON request body |
| `res.json()` | Auto-serializes the response and sets Content-Type |
