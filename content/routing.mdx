## How Express reads a URL

<Summary>
**URL** = which resource? **Method** = what to do with it? **Path parameter** = which specific one? **Query parameter** = how do I want the result?
</Summary>

## Static routes

<Summary>
A fixed URL. The path itself never changes.
</Summary>

```js
app.get('/api/products', (req, res) => {
  res.json(products) // GET /api/products → "give me all products"
})
```

Other examples: `/api/users`, `/api/orders`, `/api/categories`.

## Dynamic routes (path parameters)

<Summary>
`:productId` matches one segment and identifies **one specific** resource. Express puts it in `req.params`.
</Summary>

```js
app.get('/api/products/:productId', (req, res) => {
  const productId = req.params.productId // GET /api/products/123 → "123" (a string)
  res.json({ productId })
})
```

## Query parameters

<Summary>
For filtering, searching, sorting and pagination. Express puts them in `req.query`, and they are not part of route matching.
</Summary>

```js
// GET /api/products?category=shoes&page=2&limit=20&sort=price
app.get('/api/products', (req, res) => {
  const { category, page, limit, sort } = req.query // all strings: page === "2"
})
```

| | Path parameter | Query parameter |
| --- | --- | --- |
| Example | `/products/123` | `/products?page=2&sort=price` |
| Answers | **Which** product? | **How** do I want them? |
| Express | `req.params` | `req.query` |
| Used for matching? | Yes | No |

<Callout type="trap">
`req.params` and `req.query` values are always **strings**. `req.query.page` is `"2"`, not `2`, so convert it with `Number()` before doing math.
</Callout>

## Nested routes

<Summary>
Parent → child relationship: the orders **of** a user. Keep nesting shallow.
</Summary>

```js
app.get('/api/users/:userId/orders', (req, res) => {
  const { userId } = req.params // orders belonging to user 123
})

app.get('/api/users/:userId/orders/:orderId', (req, res) => {
  const { userId, orderId } = req.params // order 456 of user 123
})
```

If URLs start looking like `/users/123/orders/456/items/789/reviews/999`, rethink the resource design. `/orders/456` or `/reviews/999` usually works on its own.

## API versioning

<Summary>
Put breaking changes in a new version (`/v2`), so old clients keep working on `/v1` until they migrate.
</Summary>

## Catch-all 404 and route order

<Summary>
Express matches routes **top to bottom** and stops at the first match. The 404 handler goes **last**.
</Summary>

Try the e-commerce routes below. Tick the "mistake" box to see what happens when the catch-all is at the top.

<RouteMatcher />

```js
app.get('/api/products', getProducts)
app.get('/api/users', getUsers)
app.get('/api/orders', getOrders)

// keep this at the bottom: "if nothing above handled it, handle it here"
app.use((req, res) => {
  res.status(404).json({ error: 'Route not found' })
})
```

<Callout type="trap">
A request with a wrong method (e.g. `DELETE /api/v1/products` when only GET/POST exist) doesn't get 405 automatically in Express. No route matches, so it falls through to your 404 handler.
</Callout>

## Real-world example: e-commerce

<Summary>
Static + query, dynamic, nested, create, update, delete, and catch-all, all in one small app.
</Summary>

```js
const express = require('express')
const app = express()
app.use(express.json())

app.get('/api/v1/products', (req, res) => { // static + query
  const { category, page, limit } = req.query
  res.json({ category, page, limit })
})

app.get('/api/v1/products/:productId', (req, res) => { // dynamic
  res.json({ message: `Product ${req.params.productId}` })
})

app.get('/api/v1/products/:productId/reviews', (req, res) => { // nested
  res.json({ message: `Reviews for ${req.params.productId}` })
})

app.post('/api/v1/products', (req, res) => { // create
  res.status(201).json({ message: 'Product created' })
})

app.patch('/api/v1/products/:productId', (req, res) => { // partial update
  res.json({ message: `Product ${req.params.productId} updated` })
})

app.delete('/api/v1/products/:productId', (req, res) => { // delete
  res.status(204).send()
})

app.use((req, res) => { // catch-all, last
  res.status(404).json({ error: 'Route not found' })
})

app.listen(3000)
```

Define each route once. Don't register `GET /api/v1/products` twice; combine the logic in one handler.

## Best practices

<Summary>
Nouns not verbs, plural names, meaningful parameter names, query params for filters, PATCH vs PUT, shallow nesting, 404 last.
</Summary>

| Rule | Good | Bad |
| --- | --- | --- |
| Nouns, not verbs | `GET /users`, `DELETE /users/123` | `/getUsers`, `POST /deleteUser/123` |
| Plural names | `/users`, `/products` | `/user/123` and `/products/456` mixed |
| Meaningful params | `/products/:productId` | `/products/:id` |
| Filters in the query | `/products?category=shoes` | `/products/shoes` |
| PATCH vs PUT | `PATCH /products/123 { "price": 900 }` | PUT with one field |
| Shallow nesting | `/users/123/orders` | `/users/123/orders/456/items/789/reviews` |
| Consistent casing | `/users/123` | `/Users/123` |
| Don't hide operations | `DELETE /products/123` | `/products/123?delete=true` |
| 404 last | catch-all at the bottom | catch-all before real routes |
